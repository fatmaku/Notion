# Design: mobile + offline (LiveFX 1.4)

Three parallel packages. Contracts below are binding; other packages' files must not be edited.

## A. Package "mobile" – phone remote/mirror + PWA
Files: `mobile.html`, `js/mobile.js`, `css/mobile.css`, `manifest.webmanifest`, `sw.js`, `icons/icon.svg` + `icons/icon-192.png` + `icons/icon-512.png` (generate PNGs with Playwright from the SVG), `server/static.js` (allow-list: `/mobile.html`, `/manifest.webmanifest` (content-type `application/manifest+json`), `/sw.js` (served with `service-worker-allowed: /` and `cache-control: no-cache`), `/icons/<name>.(svg|png)`), `index.html` (only: `<link rel="manifest">`, theme-color meta, SW registration snippet at the end, and a "📱 Handy" card with the mobile URL + QR-free instructions), `test/e2e/35-mobile.js`, `test/mobile.test.js` (static allow-list + headers), `docs/HANDY.md` (German).
- `mobile.html`: phone-first layout (no horizontal scroll at 360 px): header with connection dot + pause + volume slider; search box; big tile grid of ALL triggers (from `LiveFXStore.load()`; tiles show `LiveFXAssets.thumbnailFor` emoji/img + label; tap = `bus.send({type:'fire', trigger, source:'Handy'})`; disabled triggers greyed); a "Szenen" row when `LiveFXSchema.SCENES` exists (fires scene triggers with matching loops like the panel's scene pad – reuse the same mapping table, copy it into mobile.js); live transcript line (listens to bus `transcript` messages and to `fire` messages → "🔥 label"); a "🎙️ Mikro" button that uses `LiveFXASR.create('webspeech', …)` + matcher when `isSecureContext` (https or localhost), otherwise shows the German hint „Mikro am Handy braucht HTTPS – siehe Anleitung“ and stays a remote control. Bus role `panel`. Reconnect status from `bus.onStatus`. Everything escaped.
- Auth: mobile.html is served like index.html; the panel cookie is set by `GET /m?token=<token>` (package B) which redirects to `/mobile.html`. The mobile page itself never handles the token. The panel card shows `http://<LAN-IP>:<port>/m?token=<token>` – the panel knows the token from `/api/config`; the LAN IP comes from `/api/config` field `lanIps` (package B adds it; guard if missing → show `location.host`).
- PWA: `manifest.webmanifest` (name „LiveFX“, short_name, start_url `/`, display `standalone`, theme/background colours, icons), `sw.js`: precache app shell on install (`/`, `/index.html`, `/overlay.html`, `/demo.html`, `/mobile.html`, all `/css/*.css` and `/js/*.js` listed explicitly, `/manifest.webmanifest`, icons), cache-first for those paths, **network-only** for `/api/*`, `/fire`, `/events`, `/assets/*`, `/docs/*`; versioned cache name `livefx-shell-v<version>` (version string injected: read from `package.json` at build? No build step → keep a constant `SHELL_VERSION` in sw.js and bump manually; also fetch `/health` version on activate to clear old caches). `skipWaiting` + `clients.claim`. Registration in index.html/mobile.html/overlay.html: `if ('serviceWorker' in navigator && location.protocol !== 'file:') navigator.serviceWorker.register('/sw.js').catch(()=>{})`.
- Tests: `test/mobile.test.js`: `/mobile.html`, `/manifest.webmanifest` (content-type), `/sw.js` (headers), `/icons/icon-192.png` (image/png) → 200; `/icons/../server.js` → 404. `test/e2e/35-mobile.js`: iPhone-like viewport 390×844: open `/mobile.html`, tiles ≥ 15, tap first tile → overlay page shows `.fx-card`; search filters tiles; pause blocks; SW: open `/` , wait for `navigator.serviceWorker.ready`, then `context.setOffline(true)`, reload `/index.html` → page still renders (`#pad`), `/js/bus.js` served from cache; `setOffline(false)`; screenshot `mobile.png`.

## B. Package "server-tls" – TLS, LAN info, cookie handshake
Files: `server.js`, `server/api-mobile.js` (new; register in server.js before static), `server/api-fire.js` (only: add `lanIps` and `secure` to `/api/config`), `docs/HANDY-HTTPS.md` (German: why the phone mic needs HTTPS, openssl one-liner, trust the cert on iPhone/Android, `LIVEFX_TLS_CERT/KEY`), `test/tls.test.js`, `test/api-mobile.test.js`, `README.md` (section „Handy & HTTPS“), `docs/CONTRACTS.md` (§4 rows for `/m`, `/api/config` fields; env vars).
- `server.js`: if `LIVEFX_TLS_CERT` and `LIVEFX_TLS_KEY` are set and readable → `https.createServer({cert, key}, handler)`; printed URLs use `https://`; log a clear German error and exit 1 when only one of the two is set or files are unreadable. Everything else unchanged (port fallback, listeners). Expose `config.secure = true/false`.
- `/api/config` adds `lanIps: string[]` (IPv4 non-internal addresses from `os.networkInterfaces()`), `secure: boolean`, `port`.
- `GET /m?token=<token>`: constant-time compare with `ctx.token`; on success set the same cookie as `auth.cookieHeader(token)` (plus `Secure` when TLS) and `302` redirect to `/mobile.html`; on failure 401 JSON (German message); rate-limit 10 attempts/minute per socket address (429). No token param → redirect to `/mobile.html` (the cookie may already exist). Register BEFORE static.
- `test/tls.test.js`: generate a self-signed cert in the test (`openssl req -x509 -newkey rsa:2048 -nodes -subj /CN=localhost -days 2 -keyout … -out …` via `child_process`; skip the test with a message if `openssl` is missing), start the server with `env: {LIVEFX_TLS_CERT, LIVEFX_TLS_KEY}` – NOTE the helper polls `http://…/health`, so add an option to `test/helpers/server.js` (`startServer({env, https: true})` → uses `https` with `rejectUnauthorized: false` for the health poll and returns an `https://` base; you own this helper change) – then `GET /health` over https works; only one var set → process exits 1 with the German message. `test/api-mobile.test.js`: `/m?token=test-token` → 302 + `set-cookie` livefx=…; wrong token → 401; 11th wrong attempt → 429; `/api/config` has `lanIps` array and `secure:false`.

## C. Package "offline-asr" – Whisper in the browser (experimental)
Files: `js/asr.js` (add backend `whisper`), `js/whisper-worker.js` (new), `scripts/setup-offline.js` (new), `package.json` (script `"setup-offline": "node scripts/setup-offline.js"`), `docs/OFFLINE.md` (German), `test/asr-whisper.test.js`, `index.html`?? NO – the panel's `#asr` select is filled from `LiveFXASR.backends`, so adding the backend there is enough; `server/static.js` is owned by package A – so serve the vendored library and models through the EXISTING allow-list by placing them under `data/assets`? No: use `/vendor/<name>.js` and `/models/<path>` → coordinate: package A adds to static.js allow-list `/vendor/<safe>.(js|wasm|mjs)` → `<root>/vendor` and `/models/<safe path with subdirs>.(json|onnx|bin|txt)` → `<dataDir>/models` (package A owns that edit; package C relies on it and tests with a fake `pipeline`).
- `LiveFXASR.backends` gets `{name:'whisper', label:'Offline (Whisper, experimentell)', supported: <true when window.Worker && isSecureContext-or-localhost && a HEAD /vendor/transformers.min.js answered 200 (cached check, async → supported reflects last check; expose `LiveFXASR.probeWhisper() -> Promise<boolean>`)>}`.
- Backend `whisper`: `start()` → getUserMedia audio → AudioWorklet or ScriptProcessor (fallback) collecting 16 kHz mono PCM; simple energy VAD: accumulate while RMS > threshold (+ 600 ms hangover), emit a chunk at silence or at 6 s max; chunks go to `js/whisper-worker.js` (a `Worker` that `import()`s `/vendor/transformers.min.js`, loads `pipeline('automatic-speech-recognition', modelPath, {device: 'wasm' | 'webgpu' when available, dtype: 'q8'})` from `/models/<model>` with `env.allowRemoteModels=false, env.localModelPath='/models/'`); worker posts `{type:'progress', pct}` during load, `{type:'ready'}`, `{type:'result', text}`; backend calls `onText(text, true, {source:'Whisper', lang, at})` for non-empty results; states `starting` (loading, `onEvent({type:'progress', pct})`), `listening`, errors → `onError({code:'whisper', message, fatal})`. `setLang(lang)` passes the language to the pipeline (`language: 'de'|'tr'|'en'`, `task: 'transcribe'`). Model selectable via option `model` (default `whisper-tiny`), stored by the panel later.
- `scripts/setup-offline.js`: on the USER's PC with internet: `npm pack @huggingface/transformers` (or `npm install --no-save` into a temp dir) → copy `dist/transformers.min.js` (+ `.wasm` files from `dist/`) into `<root>/vendor/`; download the ONNX model files for `onnx-community/whisper-tiny` (or `--model base`) from `https://huggingface.co/<repo>/resolve/main/<file>` into `<dataDir>/models/<repo>/…` (config.json, tokenizer.json, tokenizer_config.json, generation_config.json, preprocessor_config.json, onnx/encoder_model_quantized.onnx, onnx/decoder_model_merged_quantized.onnx) with progress output; idempotent; German messages; exit codes. Cannot run here (network blocked) – test only its URL/file-list builder functions by exporting them.
- Tests (`test/asr-whisper.test.js`, node:test): backend registered; `create('whisper', {...})` with an injected `workerFactory` (fake worker) and fake `getUserMedia`/`AudioContext`: start → worker receives `load` with model path + lang; progress events forwarded; VAD chunking (feed PCM frames: silence, speech, silence → exactly one `transcribe` message with ≥ N samples); result → `onText(text, true, {source:'Whisper'})`; empty result ignored; `stop()` terminates the worker and tracks; unsupported (no Worker) → state `unsupported`. `scripts/setup-offline.js` unit: exported `modelFiles('onnx-community/whisper-tiny')` list and `fileUrl()`.
- `docs/OFFLINE.md`: what it is, `npm run setup-offline` (needs internet once, ~40–150 MB), choose model, expected speed (tiny ≈ 1–2 s per chunk on a laptop), limitations, how to select „Offline (Whisper)“ in the panel, troubleshooting.
